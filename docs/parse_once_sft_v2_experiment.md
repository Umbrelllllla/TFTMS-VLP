# 特殊措辞增强 V2 试验

## 目的

V1 条件抽取适配器在两套保守语法开发集上均达到 240/240，但对 test 公共描述做不读取答案的语言审计时，900 条中有 130 条超出保守解析器的覆盖范围。V2 只从原训练划分中寻找同类表达，增强语言覆盖；test 标签没有进入样本筛选、训练或验证。

## 数据构造

训练集共找到 948 条满足“每个目标字段都有直接文字依据，数值与标注属性严格一致”的特殊措辞候选，来自 853 个文件。覆盖的表达包括：

- `sideways` / `side-facing`
- `N meters away` / `at a distance of`
- `between` / `about` / `stand ... in height`
- `that` / `these` / `those` / `whose` 等关系从句
- `object name of car` 及额外填充语句

从中抽取 256 条特殊措辞用于继续训练，另加入 256 条 V1 普通样本回放，共 512 条。再从不同文件留出 120 条特殊措辞作验证；训练与特殊验证文件交集为 0。

有 429 条候选被证据规则排除，其中 405 条是文字中的距离数值与标注属性不一致。排除这些样本是为了避免让模型学习互相矛盾的监督。

## 训练配置

从 V1 LoRA 适配器继续训练 512 步，batch size 1，LoRA rank 4，学习率 0.00005。基础模型保持 4-bit NF4 加载；训练只更新 LoRA 参数，不覆盖 V1 适配器。

- 训练耗时：2,539.4 秒，约 42.3 分钟
- 峰值显存分配：3,906 MiB，约 3.81 GiB
- 已改变的 LoRA 张量：372

## 结果

| 验证集合 | 合法且条件完全正确 | 最终候选判断 |
|---|---:|---:|
| 特殊措辞留出集 | 119/120 | 不适用（本集只验证条件抽取） |
| V1 第二套普通回归集 | 120/120 | **240/240** |

普通回归集仍为 TP=120、FP=0、FN=0、TN=120，说明加入特殊措辞后没有观察到遗忘。V2 适配器从磁盘重新加载后，锚点输出与训练完成时逐字符一致。

## 唯一严格失败的解释

特殊留出集唯一无效输出对应原句：

> Vehicles, which are white in appearance, are positioned at a distance of approximately 10 to 15 meters, and have a height ranging from 0.5 to 0.9 meters.

模型输出了高度、颜色以及 `distance_min_m=10`、`distance_max_m=15`。当前固定扁平格式只允许 `distance_max_m`，因此严格解析器因额外的 `distance_min_m` 判整条无效。

核对原训练记录后发现，文字写 10–15 米，但两个正样本车辆实际约为 22.6 米和 23.7 米；标注 `properties` 也只包含高度与颜色，没有距离。因此模型对文字的理解合理，冲突来自原始文字与正样本标注。不能把 10–15 米强行加入程序判断，否则会错误排除该标注的正样本。

所以本轮报告同时保留两个口径：严格固定格式为 119/120；语言含义抽取为 120/120，其中 1 条受数据矛盾和当前 schema 限制。正式程序仍以标注一致性为准，不因这一个案例扩展距离下限字段。

## 结论和限制

V2 已证明可以从训练集自动找到特殊措辞并增强适配器，同时保持 V1 普通验证 240/240。它仍然是训练侧留出验证，不是官方 test 得分；119/120 也不能直接换算成 900 条 test 的准确率。

本机产物位于 `runs/qwen2b_parse_once_sft_v2`，包含数据清单、训练逐步日志、原始输出、逐条评分、适配器哈希和磁盘重载检查。`runs` 目录被 Git 忽略，不会随代码仓库自动上传。
