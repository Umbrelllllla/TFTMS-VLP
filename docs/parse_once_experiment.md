# 描述只解析一次的条件抽取实验

## 要验证的问题

把每条自然语言描述先变成一份条件 JSON，随后用固定程序判断所有候选，能否同时保持准确率并缩短推理时间。

模型输入只有原始英文描述，不含候选参数、标注属性、正负答案或 test 标签。使用未加载 A/B 适配器的 Qwen3.5-2B，NF4 量化、关闭思考、贪心生成。每条描述只调用模型一次。

输出只允许以下字段：类别、颜色、画面位置、朝向、遮挡、最大距离，以及长宽高的上下限。未被文字直接提及的字段必须省略。程序对候选的现有结构化参数做严格相等或闭区间比较，不使用容差，也不修复模型输出。

## 数据与计分

沿用扩大验证实验的冻结数据：120 张开发图片、120 条描述、240 个候选，正负各 120。每条描述配一个正候选和一个困难负候选。这不是官方 test。

分别记录三层结果：

1. 输出能否通过严格 JSON 与字段校验；
2. 抽取出的所有条件是否与标准条件完全相同；
3. 程序对候选给出的最终 0/1 是否正确。

非法模型输出不会被猜测或修复，其对应两个候选均按未解决且错误计分。

## 结果

| 指标 | 结果 |
|---|---:|
| 合法条件 JSON | 106/120 |
| 条件完全正确 | 82/120 |
| 最终判断正确 | 201/240（83.75%） |
| TP / FP / FN / TN | 99 / 4 / 21 / 102 |
| 无法判断 | 28 |
| Precision / Recall / F1 | 0.9612 / 0.8250 / 0.8879 |
| 模型推理 | 637.1 秒，120 次 |
| 程序比较 | 约 0.004 秒，240 次 |

把标准条件送入同一比较程序时得到 240/240；条件完全正确的 82 条描述对应 164 个候选，也得到 164/164。因此本轮损失来自自然语言条件抽取，不是候选比较程序。

主要抽取问题为：16 条合法输出多加具体类别，7 条漏掉颜色，4 条漏掉遮挡，4 条多加画面位置；另有 14 条输出使用非法字段值。其中 6 条把泛称 `vehicle` 当类别，8 条把朝向或遮挡值写入了位置字段。

## 与 A/B 的速度比较

本验证集每条描述只有两个候选。A 直接判断 240 次耗时 453.2 秒；本方法虽然只调用 120 次，但每次要生成较长 JSON，总耗时 637.1 秒，因此本轮比 A 慢。它比生成完整逐属性答案的 B 快 13.75 倍。

官方 test 有 900 条描述和 12,660 个描述—候选组合，平均每条描述约 14.07 个候选。A 的本次 test 原始响应累计耗时约 3.55 小时。若本实验每条描述 5.31 秒的速度能迁移到 test，只解析 900 次预计约 1.33 小时，约快 2.68 倍。这个数值只是速度外推，没有在 test 上运行条件抽取模型，也不代表准确率。

## 结论与下一步

“解析一次再程序判断”的架构在候选较多时有明确速度价值，而且错误可以定位到具体字段。但基础 2B 模型零样本抽取只有 82/120 条条件完全正确，当前 83.75% 的最终准确率不足以替代 A。

下一步应训练一个只负责条件抽取的适配器，训练目标就是本实验的扁平 JSON。重点加入泛称 vehicle 不产生类别、朝向/遮挡字段归属、颜色与遮挡不可遗漏的监督。应另留未参与提示词和训练选择的新验证数据，达到至少 A 的 231/240 后再考虑替换正式推理流程。
